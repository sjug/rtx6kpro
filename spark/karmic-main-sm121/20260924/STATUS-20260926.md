### Read-only follow-up while launcher approval is pending

Main inspected pinned vLLM `1794dcf1`, not the mutable checkout, at
`deepseek_v4_1/ced.py`, `nvidia/model_state.py`, `nvidia/model.py`,
`attention.py` and `b12x_layers.py`. For ordinary requests without prompt
logprobs, CED retains `min(query_length, 128)` decoder rows. Its gather
indices are derived from the original request end and compact end; the
decoder positions are `seq_len - kept`. The inspected mapping does not
establish an off-by-one defect. The model builds full encoder-row global
KV at the CED boundary before gathering decoder rows, so a hypothesis
that it simply omits all earlier global KV is not supported by this code.

The attention wrapper accepts any live row count up to the prepared
`query_rows`; it does not require equality. Its indexer processes bounded
row chunks, and the last chunk uses `min(offset + chunk_rows, rows)`.
These checks do not prove the native kernels or earlier KV writes correct.
The remaining alternatives are CED/cache replay behavior, row-count-based
kernel numerics, and content/position sensitivity. No new defect is claimed.
