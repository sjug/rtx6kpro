## What changed in the composition method

B12X no longer has a repository: since docker #144 the images take it from FlashInfer 0.7.1, whose wheel installs `flashinfer/experimental/b12x` and a top-level `b12x` alias package (`_compat`). The base image, its identity gates (`verify.py`, `inherited/verify_runtime.py`) and both inherited launchers assert that `b12x` imports from `/opt/jovian-judgement/b12x`, first on `PYTHONPATH`. The kit keeps that root and refreshes its package from the frozen FlashInfer archive's experimental subtree (`prepare.root_package`, `_compat` excluded), so the root is byte-identical to the package the wheel embeds apart from `b12x/__init__.py`: the embedded file is only an alias stub (the wheel's `_compat` initializer does the real bootstrap, rooted at the embedded directory), so the root carries `b12x_root_init.py`, the same bootstrap rooted at `/opt/jovian-judgement/b12x` (execute `_api.py` as the package, install the `flashinfer.experimental.b12x.*` alias finder). Both import paths then share one live package; `upgrade_dependencies.py` checks the public API, the wheel-payload identity (root extras limited to the subtree's `.md` files the wheel does not package) and module identity across the two paths. The archived repository's tests, validation corpus and packaging files leave the root; the root's `b12x.egg-info` stays, so `b12x` distribution metadata resolves (vLLM's shared-PLE telemetry reads it). At assembly `upgrade_dependencies.py` removes the base's `b12x 1.3.0` wheel copy from site-packages, installs the three runtime dependencies and the three rebuilt FlashInfer wheels, and proves the root package equal to the wheel's embedded one and first on the import path.

B12X C sources changed with the move: the RoCE proxy is ABI 5 (per-peer rails, up to four HCAs) and the loader sources were reformatted. The proxy is compiled once in the Dockerfile into the prebuilt cache `/opt/b12x-roce-cache` and must load with `CC=/bin/false`, as the foundation did for ABI 4; the loader compiles at first use through the host compiler, as before. `verify_identity.py` and `verify_runtime.py` are kit copies of the foundation gates differing only in the ABI assertion (the identity copy also imports the foundation modules from `/opt/karmic-main-build`, since it runs from `/kit`); `glm/launchers/serve-glm53-flash-karmic-spark.sh` is the inherited GLM launcher with the same one-line change, installed by the Dockerfile over the image's launcher, digest-pinned and labeled (`local-inference.glm.launcher.sha256`), which the GLM runner's provenance check requires. The Qwen launcher asserts only the import root and is unchanged. `test_kit.py` pins each copy to its foundation original.

FlashInfer 0.7.1 ships three wheels: `flashinfer-python`, the `flashinfer-jit-cache` discovery shim and one architecture provider, built here as `flashinfer-jit-cache-sm121a` (`FLASHINFER_JIT_CACHE_PROVIDER_ARCH=12.1a`). The FlashInfer kernel gate requires every AOT kernel to come from that provider. The B12X test corpus moved to FlashInfer's `tests/experimental/b12x`; `build.sh` unpacks the frozen source on dusty and mounts it read-only for the compiler gate, whose corpus is now pinned explicitly (the archived tip's twelve entries plus the earlier additions).

vLLM native inputs: unchanged apart from the deferred Rust DSML files and two dependency-metadata files (`requirements/cuda.txt`, `setup.py`: FlashInfer 0.7.1 and the `b12x` extra), which ship as text; the compiled extension is not rebuilt and the installed vLLM metadata is overlaid (`flashinfer-python==0.7.1`, `flashinfer-python[b12x]==0.7.1`, CUTLASS 4.7.1). The SM121 overlay is now CMake-only: the draft-head capability gate accepts the SM120 family upstream (vLLM #995).
