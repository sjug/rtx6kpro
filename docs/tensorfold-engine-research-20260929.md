TensorFold is a separate inference implementation, not a vLLM backend switch. The pinned GLM CUDA path owns its weights, tensor-parallel split, kernels, graphs, cache, sampling, drafting, and HTTP adapter. Its two ranks gather partials across a network; the family rejects TP values other than 2. CUDA kernels use PyTorch/Triton plus compiled CUDA extensions, with the NVIDIA PyTorch container providing the CUDA toolchain rather than a TensorFold CUDA pip extra. Engine code is MIT; the recipe and every model retain their separate licenses. [Family implementation](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/families/glm5_next/__init__.py), [package](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/pyproject.toml), [license](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/LICENSE), [notices](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/THIRD_PARTY_NOTICES.md).

## Exact decoding: useful property, limited scope

The engine samples through a deterministic hash of seed, absolute token position, and token ID, then uses Gumbel-max over temperature/top-k/top-p candidates. A draft is accepted when it equals the target token that the same engine's serial execution selects. This couples speculative and serial randomness and makes byte equality a meaningful cache/kernel regression check. Without an explicit seed, the prompt hashes to the seed, so repeated identical requests are deterministic even with nonzero temperature. That is a material behavioral difference for clients expecting a fresh sample on every retry. [Exact sampler](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/engine/exact_sampling.py#L1-L109), [HTTP sampler](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/cuda/server.py#L219-L230).

This promises equivalence to the same weights, kernels, cache arithmetic, and settings, not the official model or vLLM. The pinned GLM author's original validation measured only contexts up to 2,051 on the complete two-rank model; long sparse attention initially had truncated-model evidence. The recipe's later long-context, FP8, cache, batching, and communication patches substantially expand that baseline and require their own evidence. These old limits should not be misreported as the patched recipe's current limits. [Pinned GLM validation and limits](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/docs/recipes/glm-5.3-flash.md).

### Verified sampling defect: disabled top-k is not honored

For sampled GLM requests, `decode.sample_rows` sets candidate count to `min(local_vocab, top_k + MARGIN)`, where `MARGIN=8`. With `top_k=0`, only eight candidates per rank are gathered, at most sixteen overall. The downstream generic sampler treats zero as unlimited, but only within that already truncated candidate array. The same expression appears in recipe patch 0120's `sample_multi` and patch 0200's `sample_drafts`; searching all 57 published patches found no correction. Negative `top_k=-1`, often used by clients to disable top-k, is also not normalized or rejected: the candidate selection reads seven per rank and `choose_rows` clamps the retained count to one.

This is a source-proven semantic bug, not a measured live failure. It matters for temperature greater than zero with top-k disabled, and can invalidate distribution parity despite serial/speculative equality. It does not invalidate the published sampled cells that explicitly use positive `top_k=20`, or greedy cells. Require a fix or strict rejection/normalization before generic client use, and add a synthetic flat-logit test plus serial/batched sampling checks. Sources: [GLM sampler lines 27-53](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/families/glm5_next/cuda/decode.py#L27-L53), [generic sampler](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/engine/exact_sampling.py#L93-L109), [batch sampler](https://github.com/jayleaton/glm53-tensorfold-spark/blob/80dba15d5db555b655fc81f34f04711a572de4ca/patches/0120-glm-batch-v2.patch), [batch draft sampler](https://github.com/jayleaton/glm53-tensorfold-spark/blob/80dba15d5db555b655fc81f34f04711a572de4ca/patches/0200-glm-batch-parallel.patch).

## API compatibility findings

- `seed`, `temperature`, `top_p`, positive `top_k`, `max_tokens`, `max_completion_tokens`, `draft=false`, and GLM `ignore_eos` have implementation paths. Therefore the benchmark's fixed output lengths and supplied seeds are not inherently unsupported flags. [HTTP adapter](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/cuda/server.py), [GLM adapter](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/families/glm5_next/cuda/app.py).
- The recipe adds GLM argument-tag parsing and schema-aware conversion, stop strings, two reasoning field spellings, and rejection of `n != 1`. Its stop strings apply to visible answer text, deliberately excluding reasoning and tool argument text. Batch cancellation ends the request on the next round; the single-request path may finish computing after output stops. [Parser patch](https://github.com/jayleaton/glm53-tensorfold-spark/blob/80dba15d5db555b655fc81f34f04711a572de4ca/patches/0002-glm-tool-call-parser.patch), [compatibility patch](https://github.com/jayleaton/glm53-tensorfold-spark/blob/80dba15d5db555b655fc81f34f04711a572de4ca/patches/0160-glm-openai-compat.patch).
- Unsupported controls can be silently ignored. The compatibility test explicitly sends `logprobs=true` and `frequency_penalty=0.5` and expects success without checking those semantics. The inspected pinned HTTP code and all 57 patches have no implementation of `response_format` or `tool_choice`. Thus JSON-schema enforcement, required/forced tool calls, and `tool_choice=none` should not be assumed from the phrase OpenAI-compatible. This differs from generic upstream API documentation, which mentions `tool_choice`; the GLM CUDA implementation is the relevant authority. [Compatibility tests](https://github.com/jayleaton/glm53-tensorfold-spark/blob/80dba15d5db555b655fc81f34f04711a572de4ca/tests/test_openai_compat.py), [pinned API documentation](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/docs/api.md), [CUDA implementation](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/cuda/server.py).
- The pinned CUDA streaming handler emits tool calls after `app.run` returns. It does not incrementally stream the arguments during generation, despite generic API documentation describing that behavior. A valid final tool-call object alone does not qualify agent latency or argument streaming. [Handler lines 355-364](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/src/tensorfold/cuda/server.py#L355-L364).
- The original checkpoint is multimodal, but GLM CUDA text loading is not evidence of image support. The pinned API explicitly lists images as unsupported; current main's image support is documented for Qwen dense checkpoints, not GLM. Qualify this as a text-only candidate. [Pinned API](https://github.com/ashhart/TensorFold/blob/2f8e514b0b7d615df7c971627ce3c0fb7e55d93a/docs/api.md), [current README](https://github.com/ashhart/TensorFold/blob/7a00336b2f6d1a1a3e0ba49d1ef5b4b82e927759/README.md).

## Qualification implications

Keep current serving unchanged. An original-model TensorFold experiment would be a separate TP2 candidate, not a TP4 replacement image. Establish immutable conversion and recipe provenance first. Start with short-context serial correctness, representative tools/reasoning and our exact request fields; explicitly gate disabled top-k, response-format handling, forced tools, streamed arguments, cancellation, and repeated requests. Then compare serial/drafted and solo/batched outputs, grow across sparse-attention boundaries, and test prompt resume, eviction, restart, long-context retrieval, and memory pressure on the chosen original-model quantization. Benchmark only after correctness, using matched checkpoint/settings/client where possible and reporting other comparisons as whole-stack results. The recipe author's default-model receipts cannot certify either alternative model.
